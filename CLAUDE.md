# ha-procare-connect

Home Assistant custom integration (HACS) `procare_connect`. Polls the Procare Connect parent web API and exposes per-child daily activity sensors, an `at_daycare` presence binary sensor and an activity event entity. Metadata only, never photos or videos. Public repository, so read "Privacy" before adding any data.

## Layout

- `custom_components/procare_connect/`
  - `api.py` async client. Login `POST https://online-auth.procareconnect.com/sessions/` with `{email, password, role: "carer", platform: "web"}` returns `auth_token` and `sites[]` (default site, else first; base is `base_url + "/api/web/"`). `GET parent/kids/` and `GET parent/activities/` (date filter, kid filter, `page`, follow `meta.pagination.next_page`). At least `REQUEST_GAP` (1 s) between requests. One re-login on 401. 429 raises `ProcareRateLimitError(retry_after)`. Error messages never include bodies, tokens or hosts.
  - `models.py` parsing (`Activity.from_api` drops photo/video, splits bathroom into diaper/potty by `data.type`), `DayStats`, event attributes.
  - `coordinator.py` polls today's activities, works out new events (first fetch per child only seeds; `nap_end` when a seen open nap gets `end_time`; seen ids reset at the local day change), backs off on 429 via `UpdateFailed(retry_after=...)`, prunes devices of children no longer listed (an empty list is a failed poll).
  - `entity.py` per-child device (`"<first_name> daycare"`, identifiers `(DOMAIN, kid_id)`) and dynamic entity adding. unique_id is `f"{kid_id}_{key}"`.
  - `event.py` fires each refresh's events once (tracked by `ProcareData.generation`), spaced `EVENT_SPACING` apart.
  - `sensor.py`, `binary_sensor.py`, `config_flow.py` (user, reauth, options), `diagnostics.py` (allowlist only).
  - `brand/` icons served by HA 2026.3+, generated by `script/render_icon.py`.
- Event attribute names `kid`, `time`, `summary`, `served_oz`, `consumed_oz`, `bottle_type`, `bathroom_type`, `sub_type`, `start`, `end`, `minutes` and the entity names (so entity ids like `sensor.<kid>_daycare_last_nap_ended`) are a compatibility contract. Don't rename them.

## Tests

- `.venv/bin/pytest` (HA 2026.10 via `requirements_test.txt`) and `.venv-min/bin/pytest` (HA 2026.3 via `requirements_test_min.txt`). `.venv/bin/ruff check custom_components tests script`.
- `tests/conftest.py` patches `ProcareClient` methods with `FakeProcare`; API tests use `aioclient_mock`. Time is frozen at 2026-01-15 16:00 America/New_York with US units.
- Snapshots (`tests/snapshots/`) are recorded on 2026.10 and skipped on other versions. Update with `--snapshot-update`.
- hassfest from the local core checkout: `cd ../core && PATH=$PWD/.venv/bin:$PATH .venv/bin/python -m script.hassfest --integration-path ../ha-procare-connect/custom_components/procare_connect`.

## Privacy

- Fixtures and snapshots are synthetic. Kids "Alex/Sam Example", fake UUIDs `00000000-0000-4000-8000-00000000000N`, hosts `*.example.procareconnect.invalid`, date 2026-01-15. `tests/test_fixtures_clean.py` enforces it.
- Real captures go only in `captures/` (gitignored) and through `script/scrub_fixture.py`. Private terms go in `.scrub-denylist` (gitignored), which the scrubber and tests check against all committable files and commit messages.
- Never write real children's, staff, school or tenant names, hosts or any real API data into code, tests, docs or commit messages.

## Release

Push a `vX.Y.Z` tag. The release workflow runs the tests, writes the version into `manifest.json`, zips `custom_components/procare_connect/` as `procare_connect.zip` (named in `hacs.json`) and creates the GitHub release.
